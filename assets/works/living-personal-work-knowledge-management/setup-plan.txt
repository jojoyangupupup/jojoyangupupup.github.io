# 个人工作知识管理
# 快速搭建方案
把消息、会议、文档、项目与周报串成一个可追溯、可自动化、会持续学习的个人工作系统。
工具准备  →  信息接入  →  项目沉淀  →  周报自动化  →  持续迭代
适用于：希望减少信息遗漏、提升项目追踪与周报产出效率的个人工作者
版本：快速搭建版

## 一、方案概览
项目介绍：个人工作知识管理。本方案以 Obsidian 为本地知识底座、如流机器人为数据与通知入口、DUCC 为自动化运行环境，把分散的工作信息加工成可追溯、可查询、可复用的个人知识资产。
核心原则  抓取原始数据只是第一步。每一路信息都必须经过“过滤、分类、关联项目、提取行动项与风险”后再进入知识库。

## 二、STEP 1｜工具准备
### 1. Obsidian：本地知识底座
下载地址：https://obsidian.md/。安装后新建一个本地 Vault；它本质上是一个文件夹。
Obsidian 的核心价值是双向链接。每条会议总结、消息摘要和文档更新，都可以通过 [[双向链接]] 关联到项目文档，使任何历史决策都能追溯到原始来源。
建议目录结构
Vault/
├── 01 🧠 个人工作信息/
│   ├── 01 📅 会议总结/
│   ├── 02 📝 周报总结/
│   ├── 03 📄 文档更新周报/
│   ├── 04 💬 消息总结/
│   └── 05 🗂️ iCafe 卡片/
├── 02 🌐 外部资讯收集/
└── 04 🚀 项目文档/
配置建议  目录结构确定后不要频繁改动，因为后续脚本的写入路径依赖它。目录只负责稳定承载，知识之间的组织主要依靠链接完成。
### 2. 如流机器人：数据、通知与问答入口
创建入口：如流开放平台。创建专属机器人应用后，获取 App Key、App Secret 与 Robot2c-Token。
数据入口：调用 API 拉取消息与会议数据。
结果通知：任务完成后主动提醒，例如“今日摘要已生成”或“发现项目风险”。
问答入口：后续接入 Agent 后，可直接在如流里询问工作问题。
安全要求  App Secret、Token 等敏感凭证不要写入普通文档、Obsidian 笔记或明文 memory。应放入 DUCC 密钥配置、环境变量或团队认可的密钥管理工具。
### 3. DUCC：脚本与定时任务运行环境
下载入口：度管家 → 应用魔方。DUCC 用于运行脚本、配置定时任务，并承载消息抓取、AI 加工、文件写入和通知推送等自动化逻辑。
### 本步完成标准
- 已创建并固定 Obsidian Vault 路径。
- 已创建如流机器人，并妥善保存三项凭证。
- DUCC 可运行 Node.js 脚本并支持定时触发。
## 三、STEP 2｜信息接入与加工
接入原则  每接入一路数据，都先回答：我想从这里得到什么？最终输出应围绕行动项、决策、风险、项目影响和可追溯来源，而不是堆积摘要。
### 1. 如流 IM 消息
相关文档：如流消息总结 · 申请用户授权 · 获取 app_access_token
调用 importMsgSummary API 获取服务端初步总结，再让 AI 结合个人项目背景进行二次加工。
### 推荐分类
待我处理：存在明确指向我的 Action Item。
老板 / 关键人相关：老板发言、关键决策者反馈与需要关注的态度变化。
重点项目相关：与当前主要项目高度相关的讨论、方案与风险信号。
过滤掉：闲聊、团建、红包与无关群通知。
Prompt 要点  明确写入当前项目名称、项目关键词和关键人名单。上下文越具体，分类与优先级判断越准确。
### 2. 知识库文档
所需能力：知识库文档 Skill · ugate 获取
### 抓取与加工流程
找出本周由你编辑过或重点关注的文档。
分别拉取一周前版本与当前版本。
生成版本 diff，识别新增、删除与修改。
结合项目字典解释变化对功能、风险、决策和待办的影响。
这个变化是否影响我负责的功能？
是否出现新的风险或需要跟进的决策？
原方案是否被推翻、收缩或修改？
必看清单  把部门周报、项目方案、技术设计文档等核心资料列成固定清单，每次优先处理。知识库 diff 往往最容易暴露“别人改了方案但没有同步”的信息差。
### 3. 会议、iCafe 与周报
Skills：会议 · iCafe · 周报

决策链路格式  建议为每个关键技术决策单独打标：决策内容 → 来源会议 → 日期。重点保留“为什么这样决定”以及成立的前提条件。
### 4. 本地文件
生成定时扫描脚本，监听指定目录（例如下载文件夹）。发现新增 PDF、Word 或 PPT 后，调用 OneAPI 提取摘要，并写入 Obsidian Vault 的指定目录。
### 可直接交给 AI 的需求
```text
帮我写一个 Node.js 脚本，定时扫描 ~/Downloads 目录，
对新增的 PDF / Word / PPT 文件调用 OneAPI 提取摘要，
并写入 Obsidian Vault 的指定目录。
落地时补充：扫描频率、去重、重试、文件大小上限、处理记录与日志位置。
```
### 5. 外部资讯
当前方案：洞察熊 - 让信息精准流向你。可用于抓取微信渠道数据。
过滤规则  让 AI 对照你的 OKR 与当前项目方向，只保留可能影响决策的内容。宁可少而重要，不要多而无用。
## 四、STEP 3｜项目信息沉淀
把项目概况输入 DUCC，让 AI 从日常消息、会议、文档和卡片中持续分析项目状态，并自动生成与更新“项目字典”。
项目字典的作用  它是 AI 理解工作的上下文锚点。项目背景越完整，AI 越能准确判断一条信息是否重要、是否构成风险、是否需要你采取行动。
### 项目字典建议字段
项目背景与核心目标。
版本路线图：当前版本、下一版本与关键里程碑。
关键技术决策：每条附来源与日期。
遗留问题清单：问题、责任人、截止时间与状态。
关键干系人列表：角色、影响范围与关注点。
主要风险：风险信号、影响、概率、应对方案与跟进人。
### 持续更新机制
检测到新决策时，新增决策条目并关联原始会议或文档。
检测到新风险或阻塞时，更新风险与遗留问题清单。
版本状态变化时，同步路线图与里程碑。
项目成员或职责变化时，更新干系人信息。
关键习惯  项目字典不是一次性文档。每次出现新决策、新风险和新版本信息，都要自动更新；时间积累越长，后续分析质量越高。
## 五、STEP 4｜周报自动化与项目问答
### 周报自动化
接入模型：OneAPI Comate
### 推荐流程
提供历史周报，作为内容结构、语气与表达风格参考。
基于本周会议记录、消息摘要、文档变化与 iCafe 卡片生成初稿。
通过如流机器人发送初稿，由你确认或修改。
确认后，用 Playwright 在部门周报中找到你的部分，并自动提交至 OKR 系统。
如流通知参考：单聊发消息 API。也可以通过 CLI 完成确认消息的发送。
### 周报 Prompt 约束
每个项目不超过 3 条。
每条用动词开头，突出完成的动作与结果。
结尾说明风险、阻塞或下周计划。
禁止编造数据；每条事实都能回溯到会议、消息、文档或卡片。
### 项目问答
直接使用 OneAPI LLM 进行复杂问答时，可能受上下文窗口限制而丢失信息。后续建议接入数字员工 Agent API，并把整个 Obsidian Vault 作为知识库挂载，以提高跨文档检索与长期项目问答的质量。
过渡方案  Agent 能力尚未接入前，优先让模型读取“项目字典 + 最近一周摘要 + 必看文档 diff”，避免一次性塞入整个 Vault。
## 六、STEP 5｜脚本沉淀与持续学习
这一步决定系统能否长期稳定运行。把自动化配置、项目上下文和个人偏好整理成可维护的 memory 文件，并在每次调整后同步更新相关脚本与规则。
### memory 建议记录
所有定时任务的触发时间、输入、处理逻辑、输出路径与失败重试规则。
如流账号、Obsidian Vault 路径、DUCC 任务名称与日志位置。
敏感凭证所对应的环境变量名或密钥配置位置，不记录明文密钥。
项目字典：当前项目背景、关键成员、版本、风险与遗留问题。
个人信息与偏好：姓名、团队、关注重点、过滤规则与周报风格。
### 持续校准规则

培养方式  把系统当成一个新同事：持续告诉它你的工作方式、关注重点和过滤标准。每一次纠错，都应沉淀为可复用规则。
## 七、快速验证与验收清单
完成搭建后，至少跑一次完整链路。只有同时通过“数据进入、项目更新、可用问答、通知可达和安全合规”五类检查，才算真正跑起来。
### 基础验收
- Obsidian 中出现今天的消息总结文件。
- 消息总结已经完成分类，并能识别“待我处理”。
- 会议 Action Item 包含姓名、动作、时间与来源链接。
- 核心知识库文档已完成版本 diff 与项目影响解读。
- 项目文档中的遗留问题与风险状态是最新的。
- iCafe 临期卡片能够被识别并触发提醒。
- 向 AI 提问“今天有什么待处理的事”，能得到具体且可执行的回答。
- 周报初稿能回溯到本周事实来源，且符合既定格式。
- 任务完成或发现风险时，如流机器人能够正常通知。
- 日志中没有持续报错、重复写入或重复处理同一文件。
### 安全验收
- App Secret、Token、ugate 等敏感信息未写入 Obsidian 或普通 memory 文件。
- 脚本日志不输出完整密钥或隐私内容。
- 所有 API 权限遵循最小权限原则，并设置必要的有效期与轮换机制。
- 自动提交 OKR 前保留人工确认步骤，避免错误内容直接发布。
最终判断  系统的价值不在于“抓了多少信息”，而在于能否稳定回答：今天我该做什么？项目发生了什么变化？有哪些风险需要现在处理？
注：部分链接仅在百度内部网络与相应权限环境下可访问。
